# Inari follow-up performance audit

Initial read-only production audit, 2026-10-24, followed by candle instancing. Root owns native browser measurements and final integration. This review constructed the actual CPU assembly, without a WebGL renderer, browser or Blender process. The initial baseline is the committed arrival packet `da6e6b9`; unrelated social metadata and R103 remain outside this work.

Initial evidence: `outputs/inari-followup-performance/benchmark.mjs`, `benchmark-first.json`, the historical `benchmark.json`/`visibility.json`, and per-view mesh inventories. The initial audit report at `2026-10-24T04:13:03.864Z` records inspected source hashes. The final candle-specific report is `candle-benchmark.json` at `2026-10-24T04:37:37.532Z`, generated by `candle-benchmark.mjs`. Root continued route integration between reports; only each report's paired comparison uses the same assembled scene. Repeated runs varied with other host activity. CPU timings are not browser FPS or a guaranteed user-device speedup. The harness stubs DOM/canvas and cannot load embedded GLTF textures; its geometry/transform comparisons do not establish visual quality or shader costs.

## Measured CPU costs

Actual assembly: 18,354 colliders, including 2,971 boxes; 495 extracted walking-floor meshes; 4,147 scene nodes, 3,524 meshes, 2,120 instanced meshes, 679 material identities and 82 empty groups. The complete scene contains 49.6 million instance-expanded triangles before visibility/LOD selection. That total is **not** a visible-frame triangle count. Startup assembly took 19.6–25.4 seconds across these runs. Updating all root world matrices took approximately 0.33–0.46 ms median.

| Probe | Existing walk height, ms/query | Existing collision, ms/query | Harness-only indexed floor, ms/query |
| --- | ---: | ---: | ---: |
| Station | 0.00031 | 0.0230 | 0.00009 |
| Street route | 0.0330 | 0.0263 | 0.0125 |
| Approach to shrine | 0.1223 | 0.0287 | 0.0995 |
| Mountain sample | 0.0280 | 0.0166 | 0.0087 |

The floor prototype reduces the same exact Three raycast to an 8 m XZ cell; all 1,326 sampled heights match. It exists only in the harness. This is a possible small optimization, but the measured costs are too small to explain severe continuous lag on their own. A collision index or generic transform cleanup should not be the first response to the user's report.

## Other candidates and limits

The arrival's reported builder subtotal is about 49,048 triangles, plus possible auxiliary geometry omitted from those reports; the replaced legacy station must also be subtracted before claiming net growth. It adds 15 retained dynamic train meshes, two animated leaves, no new lights and no extra animation loop.

The original viewer rendered up to DPR 1.7 (2.89 times the CSS pixel area) with 2048² PCF sun shadows updated every frame. Root added Balanced quality with a DPR cap of 1.25 and High with the original 1.7 cap. On a device that reaches both caps, Balanced submits 46% fewer framebuffer pixels; this is a pixel-area comparison, not a measured GPU/FPS gain. At device DPR 1 the cap change has no effect. Root also added `compileAsync` before starting arrival to prepare shaders; native validation of that startup change remains root-owned. Shinike reflection captures are keyed to appearance changes and gated to 220 m; visitors are limited and distance-gated. Neither is an obvious persistent arrival hotspot from source inspection.

`render-stats.mjs` wraps only `renderer.render` for `submitMs`, not the entire frame or GPU execution. Root reported one native 1280 × 720, DPR 1 observation during JR disembarkation: 83.8 FPS, 11.45 ms submission, 2,659 calls and 4,886,034 triangles. That single window does not reproduce or refute the user's lag. Use repeated fixed-camera comparisons on the final source before claiming a performance improvement.

## Rejected visibility experiment

A conservative subpixel controller was tested on the existing batching owner's explicit static output: 752 eligible meshes, but only 17 hidden at train/platform and 16 at crossing. Its eleven behavioral tests passed and its update cost was small; the actual draw reduction did not justify another visibility owner and reflection-capture coordination. Root removed its wiring and both production/test files. `visibility.json` is historical evidence of rejection, not an active implementation or final performance claim.

## Accepted candle instancing

`candle-flame-instances.mjs` converts the already supplied legacy candle flames into instances within each original house. It preserves geometry, material, rendering flags, parent transforms and the exact absolute Y-scale animation. Only four matrix elements per flame change each frame. Fixed bounds contain the complete flicker envelope, including the authored pose; no geometry is hidden or simplified.

The same controller converts wax only when it identifies all 14 unique bodies from `createRosokuCandleHouse`: exact cylinder dimensions and material, paired flame coordinates/base height, common parent/assets/flags and unchanged authored body transform. Some wax was already statically batched by integration and is left alone. Ambiguous, incomplete, hidden, directly interactive, transparent or callback-owned objects are excluded. Parent interactions stay on the original ancestor; the existing recursive raycast resolves an instance hit back to that same ancestor. `dispose()` restores the original mesh identities and last flame pose without disposing shared geometry/materials.

Final same-assembly CPU comparison, 1280 × 720, FOV 45:

| Item | Original draws | Instanced draws | Removed draws |
| --- | ---: | ---: | ---: |
| Flames in 14 houses | 196 | 14 | 182 |
| Remaining wax in 8 houses | 112 | 8 | 104 |
| Total converted candle parts | 308 | 22 | 286 |

All five sampled views—JR train, JR platform, crossing, Keihan train and Keihan platform—remove 286 main-pass mesh candidates with **zero triangle delta and zero shadow candidate/triangle delta**. This is a CPU frustum comparison, not a WebGL renderer draw count. None of the converted originals is a direct member of the 60-object interaction registry. Disposal restored all 196 flames and 112 wax bodies.

Across 250 paired-path timing samples, animation plus `root.updateMatrixWorld(true)` measured 0.471 ms median before and 0.440 ms after. These numbers show no measured CPU regression on this host; they do not explain severe lag or establish a whole-frame speedup. The earlier flames-only result is retained as `candle-benchmark-flames-only.json` (182 fewer candidates; 0.506 → 0.464 ms medians). The first full-matrix prototype's higher cost remains in `candle-benchmark-first.json` for transparency.

## Native evidence boundary

Root reported an intermediate Keihan platform comparison at 1280 × 720 / DPR 1: 2,535 calls, 3,718,104 triangles, 67.6 FPS and 14.03 ms submission before; 2,375 calls, 3,719,098 triangles, 68.3 FPS and 13.52 ms after flames-only instancing and removal of the visibility experiment. The net 160-call reduction is 6.3%; 182 removed flame draws were partly offset by 22 restored static draws. Concurrent frontage additions confound the small triangle difference. This is not a controlled FPS claim and does not include the final wax conversion. Final native route/visual checks, shader-startup behavior and DPR-quality comparisons remain root-owned.

Root subsequently completed the final route and native UI checks. With wax instancing and the expanded street context, the saved same-pose native sample reports 2,288 calls and 3,748,828 triangles (9.7% fewer calls than the earlier 2,535-call scene). The final sample records 73.9 FPS; no controlled FPS improvement is claimed.
