## Named phases and deliverables

**Phase A — Freeze and register.** Root freezes starting source revision and ownership manifest, preserves dirty files and current accepted checkpoint, and records metres, world origin/axes, height samplers, mapped IDs, floor/roof profiles and interface endpoints from existing code. Reference owner attaches evidence state to each zone. Required outputs: near-precinct plan and mountain route plan derived from actual geometry, two diagnostic sections through stair/platform interfaces, camera list and unresolved-source queue. Do not create an independent hand-drawn plan with conflicting dimensions.

Immediate active-work assignments: `approach_implementation` takes zones 01–06; `sanctuary_implementation` takes 07–17; `mountain_implementation` takes 18–34; `review_and_water_qa` owns independent diagnostic review and native water evidence. Root integrates shared files and resolves boundary conflicts. The role labels elsewhere in this document map to these exact agent names. Correction rounds happen within the active work; no scheduled automation is required.

The next major completeness packet is **Nōsatsusho–Yashima pond branch**, owned by `sanctuary_implementation` with reference support. First inspect the actual current geometry and tags for candidate `way/305214607` plus adjacent pond/path features; establish whether the pavilion already exists as a generic volume, is misattributed, or is absent. Then acquire a registered broad frontage and reverse branch view from the guide/360/video, showing Tamayama junction, pond edge and building together. Record identifiable roof form, footprint orientation, opening and public approach before changing architecture. If the mapped generic volume is the pavilion, refine that existing owner; if genuinely absent, add one source-backed building at an independently registered footprint. Do not duplicate the generic volume or spend the packet on incidental props while the destination identity is unresolved. Acceptance is a recognizable pavilion/pond composition and continuous bidirectional branch walk, with floor/footprint/roof correspondence and no new public interior invented.

The highest-impact pending evidence is that wide branch/building registration, followed by a single registered lower-precinct sequence tying Gehaiden side circulation to Gonden/Tamayama/Okumiya. These resolve missing or misidentified architecture and route relationships across several zones. A close-up fox, lamp or generic mountain corridor has less completeness value at this stage. Native whole-scene lower-precinct views remain necessary to distinguish missing architecture from objects merely outside previous isolated renders.

**Phase B — Close the near precinct.** Southapproach and northsanctuary build only exclusively assigned modules. Complete zones 01–17 in dependency order: geography/footprint, grade, stairs/thresholds, wall/roof silhouette, surface boundaries, recognizable fixtures, planting. Root alone edits shared integration, viewer, shared surfaces and collision wiring. Preserve existing deterministic batching/LOD and no-dependency approach unless a concrete need is reviewed.

**Phase C — Make the full journey continuous.** Mountain owner closes zones 18–30 and 33: both torii alternatives, Okusha exit, pond junction, both major junctions, peak chain and return. Before microdetail, run actual runtime collision/walk-height sampling plus manual bidirectional walks including doorways and lateral margins. Reference owner resolves route ambiguity rather than the builder inventing connections.

**Phase D — Account for every named side zone.** Resolve zones 17, 24, 31, 32, 34 with independently registered footprints, approach/departure and access restrictions. Where evidence is absent, retain a clearly documented incomplete mapped blockout. Do not silently relabel generic geometry as a finished named site.

**Phase E — Review actual geometry and native output.** Root exports or renders same-source lower-precinct overview and mountain overview, four fixed diagnostic angles, and real section cutaway. Inspect clay structure before beauty appearance. Native browser then verifies actual WebGL compilation, texture/normal fidelity, water under day/gold/night, interaction and collision. Offline Blender images are useful structural evidence but cannot prove WebGL shader validity or native FPS.

**Phase F — Final handoff.** Review integrated diff, run release gates, reopen the viewer and repeat changed/adjacent walks. Deliver editable sources, reference register, source-bound evidence paths, fixed-camera before/after sheet, per-zone pass/fail/unverified ledger, tests and remaining tickets. No exactness percentage. If native checks are blocked or named zones remain unaccepted, label delivery incomplete with those precise gaps.
